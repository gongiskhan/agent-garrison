### Provider implementation adjustments, 2026-09-13

- E2 correction: Slack's required user scopes also include `channels:write`, `groups:write`, `im:write` and `mpim:write` for `conversations.mark`, in addition to the brief's list. This follows the [official method contract](https://docs.slack.dev/reference/methods/conversations.mark/). The existing bot connection remains unchanged. Messages has an additive user-token account setup endpoint at `/api/connectors/slack/messages-accounts`; it verifies the workspace/user and records the exact granted scopes. Google consent now adds `gmail.modify`, records provider-returned scopes, and stores independently addressed mailbox grants while preserving the existing default account.
- E3 correction: the existing WhatsApp receive handler also forwarded every inbound text to gateway `/chat`. Enrolled mesh nodes and fittings that previously enabled Messages disable that automatic forward before connecting, so provider bodies remain data even if initial registration fails or the registry is unavailable after a restart. Successful registration persists the enabled mode. A standalone fitting that has never enabled Messages retains its existing forwarding behavior. Baileys, pairing, pacing and the existing 60-second outbox remain in place.
- E3 additive interface: `/messages-adapter/events` carries complete normalized message/conversation events; `/messages-adapter/fetchMessages` reconciles the last 24 hours from a durable journal. The journal retains action and media references for the configured provider retention period, with protected raw records available afterwards. Missing read references fail visibly. The callback supports media download, read receipts, recent own-message delete and structured send. Agent sends delegate immediately to the existing outbox with `managesAgentHold: true`; its status and cancel callbacks expose the original hold, with no second timer. Media-only messages and group participants are included. These are additions around the current socket, with no replacement library or protocol change.
- Live readiness: dev-madrid's WhatsApp view and `/health` report connected and paired; its self identity was checked on the owner without disclosing authentication material. Google Drive's own-user profile confirms the existing personal mailbox, while stored scopes still lack `gmail.modify`. CSG was unavailable with HTTP 502. The Pro currently publishes WhatsApp at port 8507 while Madrid, Mini and Air use 8487; callback routing must read the owner's actual fitting view mapping rather than assuming the usual mapping. No live message was sent during these checks.

The proposed Filter needs starred to support the specified Starred control. SystemAction needs immutable target metadata and a cancel-send action to support the requested stale-answer protection and held-send cancellation. These are additive extensions. Read state is two-way for Gmail and outbound-only for Slack/WhatsApp as section 5.2 specifies.
