# Phase 6: attachments and audio

The shared composer is used by Messages and Conversations. It supports paste, files, native camera when available, photo input fallback, Drive selection, voice preview and recording cancellation. Images have fitted thumbnails and a full-screen viewer. Audio keeps its original, produces browser-safe playback, exposes duration and speed, and indexes completed transcripts.

Eight unique media browser cases passed. Both profiles are covered: iPhone 390 by 844, device scale factor 3 and touch, and desktop 1440 by 900. Coverage includes inbound voice playback at 1.5x with advancing audio time, transcript search, photo attachment, pasted images, files and Drive links, a synthetic recorded voice send, and recording cancellation and restart. The phone cancellation case uses actual browser touch events for hold, left-slide cancellation and release to preview. The desktop case uses click controls. No cancelled recording enters the outbox.

The lead viewed all 12 final screenshots in `evidence/messages/p6`. The stems `voice-player`, `transcript-search`, `photo-attached`, `drive-picker`, `file-and-link` and `voice-preview` each have an `-iphone.png` and `-desktop.png` capture. They show complete playback controls and transcript, visible shell and conversation headers, and the composer within the viewport. The complete filename inventory is [ui-screenshot-inventory.json](../../evidence/messages/p8/ui-screenshot-inventory.json), and the final browser receipts are [ui-test-results.json](../../evidence/messages/p8/ui-test-results.json).

The phase pipeline batch recorded four passing ffmpeg tests, nine Drive fixture tests and one system attachment-copy test. Shared composer regression checks passed 77 tests. The final media boundary batch passed 41 tests across five files: five process and IPC boundary tests, four media pipeline tests, one attachment-copy test, two replay tests and 29 restricted ingest tests. The actual transcription subprocess denies state-file reads, writes and child processes, receives no credentials, and can request only transcription of an existing attachment ID from the fixed broker. The broker rejects arbitrary methods, URLs and paths and caps each attachment at three attempts. The lead's bounded second verification accepted this correction. Its receipt is [media-boundary.log](../../evidence/messages/p8/media-boundary.log).
