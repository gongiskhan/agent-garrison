# Projects as a core area

Date: 2026-09-13. Implementation and verification continued on 2026-09-14.

## Why

Files and git must remain available when a composition is down. The previous
own-port file view and app git floor duplicated project resolution and git
behavior, and neither offered a complete owning-node file and git journey.
Projects brings those operations into the shell at one origin per node.

## Decisions

- **D1. Core area.** `packages/projects` owns the server logic and UI. Shell
  routes bind it at `/projects`, `/api/projects` and `/api/workspace`. This
  follows Archive's dependency boundary and availability rationale, with a
  documented exception to roadmap c6.9.
- **D2. One resolver.** `src/lib/dev-root.ts` remains the app's canonical
  resolver. The local checkout is a normal dev-root child. Other registered
  nodes did not report enough metadata to prove A1, so `selfCheckoutProject()`
  owns the fallback alias. The package receives the resolver by injection.
  Gateway project resolution stays unchanged and parity tests cover it.
- **D3. One Projects git module.** The railed fitting module moved to
  `packages/projects/src/git.mjs`. Its public operations retain hooks and
  fsmonitor overrides, execFile, bounded execution and output, validated
  arguments and path separators. `dirtyState(xy)` supplies UI state once.
  The duplicate app git executor and FF-only floor are retired.
- **D4. App pump.** Next's Node runtime instrumentation starts the pump without
  opening Projects or starting a composition. `GARRISON_PROJECTS_PUMP=0`
  disables it. A global symbol prevents duplicate pollers during reloads.
- **D5. Read-only projects.** Project file routes only read. File writes and
  folder creation return the specified 403 body. Project viewers never expose
  an editor; changes move through git.
- **D6. Garrison files.** The existing artifact root and environment override
  remain. Workspace writes are local only. Every node's picker starts with
  Garrison files, without a Git tab. Standing artifact guidance is included in
  every capabilities detail mode, including an empty fitting selection.
- **D7. Node and project identity.** A project is `{node, project}`. Nodes list
  their own dev-root children on demand. No projects table or peer list cache
  was added. Offline nodes retain an empty, clearly explained group.
- **D8. Relative URLs.** Shared helpers use the self API or the existing mesh
  relay according to the owning node ID. Self identity is read once per page
  load. Browser URLs remain relative.
- **D9. Owning-node actions.** The relay forwards requests and status codes;
  the owner resolves and executes. Three merge POSTs receive 180 seconds,
  Fetch receives 60 seconds, and other requests keep the default proxy
  timeout. These budgets follow section 6's explicit route rules.
- **D10. No UI force.** The scripted commit-push option remains available.
  Browser request assertions prove every Git action omits `force`. Live and
  unreadable session registries stop publication with the specified result.
- **D11. Merge rails.** Non-trivial merges preserve a pre-merge tag and file a
  decision card before changing HEAD. Merge uses `--no-ff`. Lockfile changes
  and binaries are refused locally and sent through the existing merge duty;
  that duty regenerates lockfiles from manifests. Push files one merge duty
  card per target. No automatic side-selection merge option was added.
- **D12. Machines retained.** The existing remote-shell contracts still match.
  Healthy transports appear as read-only machine rows without Git. Discovery
  uses the existing fitting views API. The fitting confines its own source;
  the shell never resolves a remote machine path locally.
- **D13. Phone-first UI.** The specified phone and desktop viewports use shell
  tokens, 44 px control targets and contained wide-content scrolling. Desktop
  retains the picker rail and splits files or changes from their viewer.
  Sheets track the visual viewport. Both shell themes are supported.
- **D14. Name.** `/projects` and the Command item use `PROJECTS_LABEL` from
  `packages/projects/label.mjs`.
- **D15. Retirement.** The old fitting, app floor, status readers and scheduler
  fallback are removed. First-load composition cleanup preserves unrelated
  YAML, retries shared revisions and records only removal metadata. Historical
  records remain under `docs/decisions/history` without rewriting them. The
  owner approved scanning tracked and non-ignored source, including hidden
  source directories, while excluding installed and generated ignored files.
  The one illustrative fixture row was renamed with explicit approval; its
  behavior is unchanged.
- **D16. Scope.** This change covers browsing, workspace artifacts, git,
  owning-node relay, pump, migration, documentation and regression tests.
  Hosted forge features, branch-management views, project editors, peer file
  writes, session migration and changes to the unrelated development fittings
  remain out of scope.

## Bindings (Phase 0)

- **FINDING-E1:** The working node lists 38 repositories under its configured
  dev-root and includes the checkout. Other registered nodes did not expose
  dev-root, count and checkout membership metadata. A1 therefore requires the
  one resolver-owned self-checkout fallback.
- **FINDING-E2:** Archive starts its watcher and queue lazily through
  `backgroundReady`. The app's `src/instrumentation.ts` provides eager Node
  process startup, so Projects uses that hook. Node-only imports remain inside
  the positive `NEXT_RUNTIME === 'nodejs'` block for Next's edge compiler.
- **FINDING-E3:** Archive receives shell dependencies from its API context.
  Projects follows this pattern for resolver, state client and rendering.
- **FINDING-E4:** Documents used an idempotent YAML retirement and explicit CAS
  migration after artifact migration. Projects adds first-load cleanup and a
  metadata-only, idempotent removal record under the node home.
- **FINDING-E5:** Board card links use `/embed/kanban-loop?card=<id>`.
- **FINDING-E6:** `renderCapabilitiesBlock` assembles standing and provider
  guidance. The artifact paragraph belongs there in every detail mode.
- **FINDING-E7:** `/transports`, `/transports/<t>/files` and
  `/transports/<t>/file` still provide discovery, entries and bounded base64
  file responses. Machines remains in scope.
- **FINDING-E8:** Archive's isolated homes, shell interception, screenshot
  checkpoints and Look judge provide the browser fixture pattern. Two-node
  Projects fixtures use separate ports, homes, dev-roots and build outputs,
  with HTTPS proxies and a temporary trusted certificate for the real relay.
- **FINDING-E9:** Initial matching-line counts were src 20, packages 0, tests
  23, docs 46, fittings 24, scripts 2 and compositions 4. Current docs had 43
  matches outside decision history. Final inventory status is recorded below.
- **FINDING-E10:** In addition to explicit floor and scheduler readers, generic
  views, proxy, publication, mesh health, lifecycle and tailnet publication
  could reach the retired status file. They now exclude it before reading.
  Lifecycle cleanup uses the existing spawn ledger.

## Known gaps

No unresolved functional gap remains in the specified scope. The approved
retirement inventory passes with zero source references. Git-ignored installed
and generated composition files stay local and are outside this source scan.

The release uses `npm run node:redeploy` on the working node and verifies
HTTP 200 from `/api/projects` and `/projects` before main synchronization.
The deployment guard requires another healthy instance and rechecks live
Conversation activity immediately before stopping services. The owner approved
temporarily stashing four unrelated tracked paths for deployment, then
restoring and hash-verifying all nine protected files. Deployment and health
receipts remain on the working node; peers catch up through origin without
being restarted by this run.

## Later

Archive decides whether Garrison files should eventually join its surface.
Hosted forge features and branch-management views need separate decisions.
A project editor, peer workspace writes and session migration are not part of
this change.
