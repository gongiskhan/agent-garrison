# Archive

## Why

Archive puts the owner's documents and Garrison's memory on one searchable core
surface over the existing Basic Memory Obsidian vault. The board lens replaces
the personal Trello document board; the notes lens exposes the existing notes.

Plain files remain authoritative. Git through vault-git-sync remains their only
transport, and every node can rebuild its derived index and background jobs.

The owner's documents are pull-only: explicit conversation reads are permitted,
but automatic memory capture and improvement must not feed on them.

## Decisions

- **D1. Core, not a fitting.** Archive lives in the shell: `packages/archive` + `src/app/api/archive/*` + `src/app/archive/*` + a Command item in the sidebar. Same pattern as Improver.
- **D2. Files are the only source of truth.** The vault (plain markdown and files, Obsidian-compatible, moved by git through `vault-git-sync`) holds everything the user sees. Any index, extracted text cache, job ledger or thumbnail is derived, local to the node, rebuildable from the files, and never synced.
- **D3. Memory stays a faculty; basic-memory stays the provider** (hooks, MCP tools, capture, Basic Memory index for agents). It gains no browsing UI; Archive is the UI. The `knowledge` faculty slot stays as it is for `roadmaps`, `pdf`, `project-viewer` (they are agent capabilities, not vault views). The `documents` fitting is retired (section 11.2). Nothing else in the default composition changes.
- **D4. Two areas, one rule each.** `Archive/` at the vault root is the owner's area: agents read it, never write it. Everything else in the vault is Garrison's area: agents write it, the owner reads and may edit or prune it. Provenance lives in frontmatter.
- **D5. Pull-only for the owner's area.** Nothing automatic (session capture, startup briefs, Claude native mirror, improver evidence collectors, Nightly Sync learnings) reads `Archive/`. Agents reach it only through explicit search or read in a conversation where the owner asked.
- **D6. Ingestion writes sidecars next to the source file**, marked derived, regenerable, never hand-edited. It is the only automatic writer inside `Archive/`.
- **D7. One inbox folder** (`Archive/Inbox/`) is the entry point for anything not yet filed: uploads from the UI, imports, and later any agent-fetched file. Connectors are out of scope for this task; the inbox is the seam they will use.
- **D8. Trello is a one-shot import, never a live sync.** Idempotent on card id so it can be re-run safely, but it does not watch Trello afterwards.
- **D9. Board lens for the owner's area, notes lens for Garrison's area, by default.** Either lens can be opened on any folder; the default is by area.
- **D10. No Obsidian clone.** No graph view, no plugin system, no wikilink resolution beyond rendering `[[name]]` as a search link. Monaco on desktop, a plain textarea with preview on the phone. Obsidian remains the heavy editor.
- **D11. Phone-first.** Designed at 390x844 first, then desktop at 1280x800. Runs inside the Garrison iOS webview unchanged.
- **D12. The name is Archive.** "Vault" is the credentials vault; "Knowledge" is a faculty. If the owner renames it later, the name is one constant (`ARCHIVE_LABEL`) plus the route.
- **D13. Scope of this task:** board, card page, notes lens, search, inbox, status strip, ingestion, Trello import, agent rules, retirements, docs, tests, walkthrough. Out of scope: connectors pulling files, shared/multi-user access, remote backends, Ekoa.

- **D20. Boundaries precede implementation.** Work is on dev-madrid/main, based
  on `bfe91b58`. All fixtures are generated from literal synthetic strings; no
  real document is copied into code or evidence. Real-vault inspection in Phase 0
  reads metadata only. Shared continuity notes hold engineering decisions only.
- **D21. Preserve authored Markdown.** Use the existing `yaml` dependency's
  document representation for unknown keys and ordering. Sidecars may be edited
  in Obsidian, but those edits last only until the next regeneration.
- **D22. Automation excludes Archive-derived conversations.** The existing
  collectors consume transcripts rather than walking the vault. Exclusions must
  therefore reject source paths and evidence referencing Archive reads, before
  any review model receives it. A path-only glob is insufficient for D5.
- **D23. Missing tools are explicit.** Use operating-system binaries already
  installed. Missing HEIC or PDF conversion produces the specified failed state;
  unsupported Office/audio formats remain unsupported. No native dependency is
  added for extraction or thumbnails.

- **D24. Extraction has no durable conversation.** Reuse the gateway's existing
  runtime adapter, resolving the configured composition target and scoped
  credentials in the shell. Invocation is lean, `persistSession: false`,
  `settingSources: []`, strict empty MCP config, and only `Read` enabled. This
  preserves the proven local-image mechanism without a transcript for automatic
  collectors. Runtime output and usage return directly to `look()`; they are
  never published into shared state. Schema validation retries once.

- **D25. Hook startup.** The standalone Node 20 ESM loader measured about
  32 ms per process on Madrid. Setup compiles the guard's same stdlib functions
  into the registered Node command (no second source and no resident process).
  The actual installed command is timed by the guard test, below 30 ms warm.
  Rendered configuration remains cached by settings mtime as specified.
- **D26. SDK harness coverage.** Full and lean Agent SDK harnesses omit user
  settings deliberately. When Basic Memory's rendered guard config exists,
  the adapter loads its installed hook and adds the same matcher and predicate
  programmatically. This preserves ownership in coding, full and lean modes.
- **D27. Recovery details.** Trash entries are unique timestamped wrappers with
  an original-path record. Restoring a colliding attachment retains its extension
  and updates the sidecar's relative source. Concurrent index updates serialize
  locally; card files and all Garrison markdown remain the source of truth.

- **D28. Desktop editing assets.** Monaco uses its installed package assets through
  a confined same-origin static route under `/archive/editor-assets/`. No browser
  request depends on a CDN or a machine-local absolute URL.
- **D29. Migration preservation.** Archive defaults are inserted through the
  existing composition migration path without reflowing authored block YAML or
  dropping comments. Peer commits of equivalent defaults are retained semantically.
- **D30. Browser evidence.** Each browser journey starts an isolated shell, home
  and fixture vault. The surrounding shell APIs are stubbed; Archive APIs, files,
  mutations and job processing run for real. Vision calls use the internal token
  and synthetic screenshots copied into the scratch vault only.
- **D31. Optional runtime loading.** The shell loads the existing SDK fitting
  natively only when `look()` runs. Shell builds do not bundle or require an
  optional fitting's private dependencies; its normal setup owns installation.

- **D32. Unsaved navigation.** A shell-mounted listener registers before the
  router and acts only while an Archive editor is dirty. Cancelling browser Back
  preserves the mounted editor and URL; link navigation and reload also prompt.
- **D33. Hook timing isolation.** The installed command replaces its shell with
  Node and uses native realpath. Tests time the complete command from a minimal
  host process, including startup and IO, excluding Vitest's own fork overhead.
  The warm wall-clock threshold remains 30 ms.

- **D34. Ingestion call accounting.** Every model invocation, including the
  validation retry, consumes the persisted hourly allowance. Returned usage sums
  both attempts. Manual regeneration resumes an existing delayed/failed job so
  the failure count clears when that file succeeds.
- **D35. Verbatim extraction.** Sidecar parsing uses the final Fields delimiter
  and preserves the Text section's source whitespace and literal Markdown headings.
- **D36. Stored HEIC recovery.** Upload converts when a tool is available. A
  previously stored HEIC can later regenerate through a temporary JPEG for the
  model; the original source remains unchanged.

- **D37. Screenshot boundaries.** Playwright trace filmstrips and automatic
  failure screenshots are disabled. Screenshots are taken only by checkpoints
  that refuse an expanded sensitive card. Older trace archives were removed from
  this task's scratch evidence; explicit checkpoints, judgments and logs remain.

- **D38. Trello request bounds.** All requests on a client share four slots,
  including nested board/list/comment fetches. API and attachment requests honor
  Retry-After (including zero and HTTP dates), back off on server errors, and
  release cancelled waits. Redirected downloads receive OAuth only on Trello.

- **D39. Preview counts.** Board selection fetches list/card/attachment metadata.
  Detailed preview skips comment requests for known-empty cards and counts the
  comments actually returned for other cards; positive Trello badges can include
  entries its actions endpoint no longer returns. Import still fetches each card
  through the full mapping path.

- **D40. Migrations and snapshots.** Archive defaults join the composition
  writer’s existing atomic save and authority CAS. Export snapshots are taken
  after read migrations, so the first export is already deterministic.

- **D41. Page lifecycle.** The first read waits one microtask so a throwaway
  development mount does not start I/O. Reads and polling pause on beforeunload
  and pagehide, then resume on persisted pageshow or focus/input after a
  cancelled leave. Aborted responses cannot replace newer data.
- **D42. Import indexing.** Watcher bursts resolve each card once, scan only
  changed folder subtrees and persist one index snapshot. Creating many card
  folders does not reread unrelated memory notes or rebuild the whole vault.
- **D43. Import request logs.** The service connects the Trello client logger to
  its job ledger and awaits each path-only entry; query credentials never enter
  the log.

- **D44. Bounded rasterisation.** Scanned PDFs whose rendered longest side would
  exceed 4,000 px use a 2,000 px raster bound before Poppler allocates the images.
  Normal pages remain at 110 dpi. Extraction binaries time out after 120 seconds;
  source files are unchanged. A synthetic large-MediaBox regression asserts the
  actual output dimensions and a sleeping-process test asserts termination.

- **D45. Legacy migration.** The retired fitting's original artifacts are retained.
  Migration copies their markdown and unknown frontmatter to collision-safe note
  names before removing selections, preserving dates and `migrated_from`.
  Redirects rebuild from that provenance if local derived data is deleted.
  Current documentation uses Archive; dated verification and immutable historical
  run artifacts retain their facts with a supersession notice instead of rewriting
  evidence. Legacy API writers are removed.

- **D46. Closing regression scope.** The artifact CLI suite exclusively exercised
  the deleted private Documents CLI and retires with it. Surviving artifact and
  file-browser behavior remains tested. Old Cortex assertions predated the
  explicit provider choice committed in `06824134`; tests now allow that exact
  configured origin while rejecting lookalikes and credential-bearing URLs.
  No provider settings or excluded product code were changed. Closing checks
  run with inactive peer work preserved outside the committed checkout.

- **D47. Document covers are images.** One closing vision judgment treated the
  synthetic certificate scan as a text placeholder despite its loaded pixels.
  The home rubric explicitly recognizes scans of printed text as image covers;
  the browser test additionally asserts nonzero natural dimensions for every
  tile image. The requirement for actual image covers is retained. The failed
  judgment and screenshot remain with the owner-local evidence.

## Scoped review — Phase 6

One lead-context review covered the seven specified questions on 2026-09-12
(local date), against committed Archive changes through `a8c8dd2c`. It found:

1. A cached thumbnail symlink could serve a file outside the permitted cache.
   Cache directories and files now require confined, regular resolved paths;
   invalid or dangling links fall back to the confined original.
2. A native mirror source containing the vault, or a symlink into Archive,
   could bypass a check of the source directory alone. The shared predicate now
   checks the input tree and rejects Archive paths and their ancestors before
   the mirror reads any body; malformed traversal fails closed.
3. Trello attachment names differing only in case could overwrite on macOS.
   Mapping now allocates case-insensitive names and reserves sidecar filenames.
4. List metadata writes could overwrite a concurrent external edit. The final
   atomic write now compares the prior content and returns a conflict.
5. Watcher orphan cleanup could interleave with a slow source/sidecar move.
   Watcher cleanup and user file operations now serialize together, separately
   from long import jobs so external note changes remain promptly indexed.

All five fixes have regression tests: outside/dangling thumbnail links, mirror
ancestor/symlink inputs, case-colliding imports, an injected concurrent list edit,
and an intentionally slow paired move, plus prompt watcher admission during a
remote import wait. All 50 affected tests pass. No data model
or architecture change was required for questions 1, 2, 3 or 5, so no second
review is scheduled. No adversarial or security-review duty was run.
